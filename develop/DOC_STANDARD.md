# 官网版本数据维护规范（DOC_STANDARD）

> **文档定位**：官网分发站版本数据（`docs/data/versions.json`）与官网版本页面更新日志的权威撰写规范。定义了日期时间格式、更新日志内容取舍原则、版本数据与更新日志/版本发布记录的联动关系。
>
> **文档结构**：
> - 按「适用范围 → 日期时间规范 → 更新日志内容原则 → 与其他文档联动 → 检查清单」顺序编排
> - 与 `develop/CHANGELOG.md`（变更日志）、`develop/PUBLISH.md`（版本发布记录）、`docs/data/versions.json`（官网版本数据）配合使用
>
> **更新规范**：
> 1. 【必须】官网发布新版本时按本文档撰写版本数据（versions.json 的 date/log/download 字段）
> 2. 【必须】修改官网版本相关规则 → 同步更新 `develop/CHANGELOG.md` 与 `DOCUMENTATION_INDEX.md`
> 3. 【如果】调整官网下载流程 → 同步更新 `docs/README.md`

---

## 一、适用范围

- **官网版本数据**：`docs/data/versions.json`——记录每个已发布版本的名称、日期时间、更新日志、四平台下载链接
- **官网版本页面**：由 versions.json 渲染的「更新日志」与「历史版本」内容
- 与 `develop/CHANGELOG.md`、`develop/PUBLISH.md` 定位不同：

| 文档 | 读者 | 内容侧重 |
|------|------|----------|
| `CHANGELOG.md` | 开发者 | 每次提交的完整变更（含内部重构、代码整理） |
| `PUBLISH.md` | 面向玩家公告素材 | 每个版本的发布信息 + 面向玩家摘要 |
| `versions.json`（本规范管） | 官网玩家 | 每个下载版本的用户可见更新日志 + 下载链接 |

## 二、日期时间规范

### `date` 字段必须带具体时间

- **格式**：`yyyy-MM-dd HH:mm`（如 `2026-08-18 09:43`）
- **禁止**：只写日期不写时间（如 `2026-08-18`）
- **取值**：该版本最后一次更新版本下载地址的 git 提交时间（与 `PUBLISH.md` 的发布时间戳一致）

## 三、更新日志内容原则

### 【必须写】用户可感知的价值

- **新增功能**：玩家能直接感受到的新特性（如"页面切换过渡动画"）
- **修复的 Bug**：玩家会遇到的问题被修复（如"安卓平台背景音乐随机切换偶发双播"）
- **性能/体验优化**：对玩家有感知的提升

### 【不写】内部实现 / 修复细节

> 核心原则：**能写进更新日志的，必须是对玩家有可见价值的东西；纯内部工程实现、本该做好的底层能力，不是更新日志的内容。**

反例（不该写进玩家更新日志）：
- ❌ "过场动画控件预偏移——动画开始前将控件提前定位到动画起点"
- 原因：动画控件从起点播放是动画的**基本正确性**，任何动画系统都该做到，玩家不会因为"动画从正确位置开始"而当卖点。这类属于内部修复/工程正确性，不写入玩家可见更新日志。
- ❌ "重构 xxx 类结构"、"统一 import 路径"、"调用链优化"——纯开发者视角，玩家无感知

判据：**如果去掉这条，玩家（不懂代码的用户）是否感觉不到差别？** 是 → 不写。

### 【必须补】跨版本才生效的修复

- 打包完成之后才修复的 bug（未随上一个版本发出），**必须算入下一个版本的更新日志**，不要遗漏
- 例如：某个 bug 在上个版本发布后才修复，玩家下载的是上个版本（没修复），那么下一个版本必须告知"此 bug 已修复"

## 四、与其他文档联动

| 文档 / 文件 | 联动关系 |
|------|----------|
| `develop/CHANGELOG.md` | 修改本规范 → 在 CHANGELOG 记录；整理玩家可见修复时从 CHANGELOG 的历史条目中筛选 |
| `develop/PUBLISH.md` | 同版本号、同发布时间戳、同"最后一次更新 commit"；`versions.json` 的 `log` 可复用 PUBLISH 的面向玩家摘要 |
| `DOCUMENTATION_INDEX.md` | 新增/重命名/删除本文档 → 更新索引；索引中描述本文档定位 |
| `docs/README.md` | 修改官网下载流程说明 → 同步 |

## 五、发布登记检查清单（versions.json 单版本条目）

- [ ] `date` 为 `yyyy-MM-dd HH:mm` 完整时间，与 commit 时间一致
- [ ] `log` 只含玩家可感知的新功能 / 修复的 Bug / 优化
- [ ] `log` 不包含纯内部实现、本该做好的底层正确性修复
- [ ] 上一版本发布后才完成的用户可感知 Bug 修复已补入
- [ ] 四平台（Windows / Android / Linux / macOS M + Intel）下载链接齐全、描述正确
- [ ] `newest_version` / `newest_version_type` / `newest_version_string` / `newest_version_snapshot` 与 `assets/asset/app_version.json` 一致
- [ ] `PUBLISH.md` 已同步该版本发布记录（含相同时间戳与 commit）
